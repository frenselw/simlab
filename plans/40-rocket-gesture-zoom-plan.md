## 一 目標與完成條件

學生應能在不打開任何鏡頭設定選單的情況下，完成以下動作：

1. 在手機畫面上以雙指放大或縮小火箭及景物。
2. 在桌面以滾輪或 touchpad 操作同一種縮放。
3. 縮放後繼續轉動視角、拖放零件或觀看飛行，操作不互相搶奪。
4. 需要時直接回到當前視角的正常構圖。
5. 切換成果頁或視角後，回到原本記住的鏡頭倍率及方向。

完成的判斷以可見畫面及實際輸入為準。只看到 `scene.zoom` 改變、測試程式直接呼叫縮放函式，或手機外觀的桌面截圖，都不足以證明功能完成。

本次保留「近景、跟隨、全景、軌道」四種視角及共用全螢幕入口。移除的是「鏡頭設定」摺疊區與其中三個按鈕。固定儀表、飛行控制、文字大小不隨 3D 縮放改變。

## 三 對使用者的操作規格

### 輸入與動作

| 輸入 | 起點 | 行為 |
|---|---|---|
| 手機雙指張開或合攏 | 兩指都由中央 3D 操作區開始 | 連續放大或縮小 |
| 手機單指拖動 | 中央空白位置 | 轉動視角 |
| 手機單指拖零件 | 火箭已裝零件或元件卡的拖動把手 | 沿用組裝操作；雙指接管規則見下節 |
| 滑鼠滾輪 | 中央 3D 操作區內，包括未正在拖動的火箭本體 | 向上放大，向下縮小 |
| Touchpad 捏合 | 游標在中央 3D 操作區 | 縮放 |
| Touchpad 雙指上下滑 | 游標在中央 3D 操作區 | 按垂直滾動量縮放；水平分量不新增平移行為 |
| 滑鼠左鍵拖動空白處 | 中央 3D 操作區 | 轉動視角 |
| 雙擊或雙點空白處 | 中央真正空白位置 | 回復當前視角的正常方向及 1 倍構圖 |
| 鍵盤 `+`、`=`、`-` | 鏡頭操作區已聚焦 | 以既有 1.2 倍級距放大或縮小 |
| 鍵盤方向鍵及 `Home` | 鏡頭操作區已聚焦 | 方向鍵旋轉；`Home` 回正當前視角 |
| 左右捲頁帶滑動 | 任一捲頁帶 | 捲動外層頁面或實際 Moodle 宿主 |
| 下方或右側控制面板滑動 | 面板文字、空白或普通按鈕 | 面板原生捲動 |

鍵盤捷徑僅在鏡頭區聚焦時接管；不能攔截文字輸入、下拉選單或瀏覽器的全頁快捷鍵。`Escape` 取消未完成手勢，保留已到達的鏡頭位置，零件則保留取消前的正式組裝狀態。

### 倍率及觀察中心

倍率沿用 `0.4–2.5`，預設為 `1`。先完成這個範圍的實際畫面驗證，若特定視角需要改變上下限，必須以裁切、近面距離及可操作性證據決定。

| 視角 | 縮放中心及構圖 |
|---|---|
| 近景組裝 | 目前火箭的正常裝配構圖中心；保留未完成火箭上方預留空間 |
| 跟隨 | 目前跟隨的火箭或分離後上級；中心不因兩指中點移動而漂走 |
| 全景 | 既有地球與軌道構圖中心 |
| 軌道正視 | 既有軌道平面構圖中心，倍率與全景分別記住 |

用戶主動放大時，可以讓局部模型或地球超出畫面；不要再用自動全圖將倍率拉回。必須保留安全鏡頭距離及回正入口，避免鏡頭穿入模型或地表。

雙指中點的平移、兩指扭轉、自由移圖及縮放慣性不屬於本次操作。放手後不額外漂移；touchpad 繼續送來的滾輪慣性事件則按同一輸入規則處理。

### 回正與提示

回正沿用目前 `setView(view, true)` 的用途，僅重設當前視角，不清除其他視角記憶、零件或飛行資料。組裝回正仍需按當前完整火箭重新計算能容納的正常構圖。

雙點辨識初始採兩次短點相隔不超過 320 ms、兩個落點不超過 24 CSS px、每次移動不超過既有 6 CSS px 拖動門檻。這些是待真機校準的互動參數。兩次都必須是同一視角的空白操作；任何零件命中、接點、工具列、雙指、拖動或取消都清除候選。桌面雙擊與自行辨識的觸控雙點不得重複觸發回正。

首次可操作時在畫面內短暫顯示「單指轉動・雙指縮放・雙點空白回正」，桌面則顯示「拖動轉動・滾輪縮放・雙擊空白回正」。沿用既有提示樣式、約 3 秒後收起、不攔截點擊、不增加面板固定高度。完整操作也加入鏡頭區的可讀名稱或說明；鍵盤提示可在聚焦時讀取。提示狀態只保留在本次頁面記憶體。

## 四 手勢接管與取消

### 區域歸屬

手勢資格按實際起點判斷，不能只看移動後游標位於哪裡。以下區域共用明確的中央邊界：

| 區域 | 一指用途 | 可參與雙指縮放 | 說明 |
|---|---|---|---|
| `cameraSurface` 中央空白 | 旋轉 | 是 | 排除側帶及覆蓋的操作按鈕 |
| 中央範圍內的 `rocketGrip` 已裝零件 | 選取或搬動零件 | 是 | 接管前取消未提交拖動及預覽 |
| 裝配接點按鈕、視角按鈕及其他工具列 | 原按鈕用途 | 否 | 不因透明背景或位置接近而被當作空白 |
| 元件卡、卡片拖動把手、控制面板 | 加入零件、拖放或捲動 | 否 | 即使拖到畫面內也不改變起點歸屬 |
| 左右捲頁帶 | 宿主捲動 | 否 | 兩側各維持可用的 32 CSS px；混合觸控裝置亦保留 |
| 非操作儀表或提示覆蓋區 | 沿用既有穿透行為 | 按實際底層操作區判斷 | 不新增隱藏攔截層 |

僅中央鏡頭區及原有真正拖動目標使用預先設定的 `touch-action: none`。面板與捲頁帶保持各自的原生捲動策略。不在第二指落下後切換全頁 touch-action、不鎖 html/body，也不以持續寫回 scrollTop 模擬鎖定。

### 手勢狀態與轉移

狀態名稱用來說明行為，實作可沿用既有變數，不必建立新的通用狀態機套件。

| 目前狀態 | 事件 | 下一步及資料處理 |
|---|---|---|
| 空閒 | 第一指在中央空白落下 | 進入單指鏡頭；保存指標 ID、起點與現時鏡頭 |
| 空閒 | 第一指命中已裝零件 | 沿用零件預覽；正式組裝只在合法放手時提交 |
| 單指鏡頭或已裝零件 | 第二指也由中央合資格區落下 | 保留當前鏡頭；取消零件預覽，轉入雙指縮放；接管一刻倍率不跳 |
| 雙指縮放 | 任一指移動 | 只按兩指距離更新倍率，不旋轉、不安裝零件 |
| 雙指縮放 | 放開其中一指 | 保留最後倍率，進入等待全部放開狀態 |
| 等待全部放開 | 餘下手指移動或再次加入第二指 | 不旋轉、不拖件、不重新開始縮放；全部放開後才接受新操作 |
| 任一模擬手勢 | 第三指加入 | 取消進行中的手勢，等待全部放開 |
| 零件箱拖動 | 第二指加入 | 取消未完成拖放；不轉為縮放，等待全部放開 |
| 中央操作 | 第二指由面板或側帶開始 | 取消模擬手勢，不接管外部起點的原生操作 |
| 任何狀態 | `pointercancel`、失去 capture、Escape、視角或頁面切換 | 清理預覽、capture、待處理輸入及雙點候選，不提交零件 |
| 任何狀態 | 失焦、隱藏頁面、改變尺寸或全螢幕 | 取消現有手勢；飛行是否暫停按既有生命周期處理 |
| 任何狀態 | WebGL 或 Canvas 資源失效 | 清理手勢並沿用 P49 暫停與恢復；恢復後等待新的輸入，不重播舊增量 |

一指已開始旋轉後，第二指加入時保留接管當刻的方向，不倒退到第一指落下前。零件預覽取消則必須還原正式組裝，不保留未放手的搬動。

### 實作時容易遺漏的細節

- 起點 ID、pointer type 及中央資格從 pointerdown 保存。處理被 capture 後送到其他元素的事件時，不重新解讀起點。
- 轉交兩個指標的 capture 時，先完成狀態切換，再釋放舊目標；舊目標的 lostpointercapture 不能誤取消剛建立的雙指手勢。
- 所有清理方法可重複呼叫；pointerup、lostcapture 及視角切換連續發生也只清理一次。
- 縮放或取消後產生的合成 click 不能選取、安裝、拆除零件或觸發回正。原本 Enter 產生的鍵盤 click 要繼續有效。
- 追蹤混合輸入：滑鼠拖件時觸控加入、觸控縮放時滾輪輸入，都不能形成兩個同時改鏡頭的擁有者。
- 非法或過小的兩指距離不作除數。兩指少於 24 CSS px 時先等待足夠距離，再以當時倍率建立基準，避免突然放大。

## 五 鏡頭計算與畫面一致性

### 將自動構圖和手動縮放分開

採用既有透視鏡頭及移動鏡頭距離的方式。先整理 `draw` 中四個視角的正常構圖，再將用戶倍率套用一次，避免同時改變鏡頭焦距與距離。

計算次序如下：

1. 用火箭尺寸、高度、視角及分離動畫進度，計算正常構圖距離 `baseDistance`；此值不包含手動倍率。
2. 用正常構圖距離決定既有火箭顯示比例、跟隨目標與近地接觸位置。
3. 將最終鏡頭距離設為 `baseDistance / zoom`，再套用必要的地表安全限制。
4. 以最終鏡頭更新投影、near/far、天空、地形細節及互動命中區。

固定同一飛行狀態比較不同倍率時，火箭模型的 world scale、落地位置及兩級的世界距離不應因手動倍率而改變。改變的是相機觀察距離與螢幕投影。

目前 `distance` 也用於決定火箭可見大小、分離近景過渡、像素比例及細節顯示，不能只在原公式外多加一次除法。需逐個用途確認應使用正常距離還是最終距離。`zoom=1` 應維持現有正常構圖；分離過渡仍沿原本時間進行，使用者倍率不可被過渡重設。

### 各畫面元素的處理

| 元素 | 使用的尺度與要求 |
|---|---|
| 上級與下級 | 沿用物理位置及既有世界單位；倍率只改投影，不能再令下級視覺上長時間貼住上級 |
| 地面與發射台 | 使用既有高度及安全鏡頭限制；低角度放大、縮小都不能穿地 |
| 速度與推力箭號 | 沿用已校準的螢幕長度與物理量比例，包括全景比例；更新計算後仍在火箭外側 |
| 裝配接點及拿取區 | 在同一畫面更新中重投影；維持現有最小觸控區及以 CSS px 計的吸附容差 |
| 零件拖動預覽 | 第二指接管立即清理；重新開始拖放時使用新鏡頭的拾取與接點 |
| 高度、速率、燃料及操作按鈕 | 保持介面原尺寸，不被 CSS transform 一起縮放 |
| 天空、地球及地形 | 使用最終鏡頭與既有細節層級；檢查向上望、近面裁切及地形切換 |
| 已提交成果 | 允許縮放與旋轉；唯讀及凍結規則保持有效 |

### 縮放數值

雙指倍率使用「開始倍率 × 現時兩指距離 ÷ 開始距離」。手勢接管時以當前倍率建立基準，因此不跳回 1 倍。達到上下限後更新距離基準，使手指反向移動能立即離開邊界，不需要先補償一段被截掉的距離。

滾輪沿用 Circuit 的單位正規化：pixel 直接使用、line 先以 16 CSS px 換算、page 按中央操作區高度換算，再以指數比例轉成倍率。以 `exp(-clamp(delta, -600, 600) × 0.0015)` 作初始靈敏度基準；最終手感需以實體滾輪及 touchpad 校準。輸入必須是有限數值，無效資料或零位移不造成重畫。

同一個鏡頭縮放入口負責有限值檢查、倍率上限下限及更新通知。Pinch、wheel、鍵盤不能各自維護一套倍率規則。

## 六 瀏覽器與效能策略

### 輸入事件相容性

手機以 Pointer Events 追蹤兩個觸點。桌面以 `wheel` 處理滾輪與相容的 touchpad 輸入，包含 `ctrlKey` 形式的捏合事件。只有落在中央合資格區、且本次互動由模擬接管時，才阻止該事件的瀏覽器預設用途。若中央正在拖件或進行雙指手勢，滾輪仍由這個既有操作擁有者攔下，但不套用額外縮放，避免頁面突然捲動或兩個輸入同時改鏡頭。

Safari 的 `gesturestart/gesturechange/gestureend` 可能需要專用相容處理。實作時先核對支援與實際事件序列；如需要補充，必須使用與 Pointer Events／wheel 相同的縮放入口，且整個手勢只選一種來源，不能在收到兩套事件時重複放大。手機已有兩個指標時，不再疊加 GestureEvent 的倍率。

不能全頁停用瀏覽器縮放，亦不能更改 viewport meta 來取代局部手勢管理。面板、工具列及其他頁面區域保持原本的閱讀和捲動能力。

參考：[MDN wheel 事件](https://developer.mozilla.org/en-US/docs/Web/API/Element/wheel_event)、[MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)、[Apple GestureEvent](https://developer.apple.com/documentation/webkitjs/gestureevent)。這些資料說明事件機制，不能代替目標裝置實測。

### 更新與效能

沿用目前 render loop，將同一幀收到的多個縮放增量合併，只以最新倍率安排一次鏡頭繪製與接點更新。飛行中由既有幀更新帶出畫面；暫停時安排一次必要的畫面更新。無輸入時不額外啟動永久繪圖迴圈。

相機操作不呼叫完整的作答 `render()`、不重建整個控制面板、不觸發模型存檔。也不能為每個 wheel 或 pointermove 重新計算軌道線、重建火箭或重畫 Canvas 貼圖。地形因可見範圍而發生的正常細節載入仍沿用既有快取與預算。

檢查連續輸入的回應、繪圖次數、模型建立次數及暖機後的 geometry／texture／program 數量。反覆縮放可觸發正常地形細節切換，但資源使用必須在快取預算內收斂，不能每次循環持續增加。不預先承諾某個真機 FPS。

### 階段與合法續作矩陣

| 階段或變體 | 縮放權限與觀察對象 | 驗收中的合法續作 |
|---|---|---|
| 空白／部分組裝，未裝太空艙 | 可操作現有組裝視角 | 縮放後點選或拖入引擎／燃料箱，亦可進入成果檢查 |
| 完整組裝及已選零件 | 可縮放；已選狀態不能變成誤拆 | 取下或裝回合法零件，再去發射台 |
| 正在拖零件 | 按手勢接管規則處理 | 取消預覽後重新開始一個可成功提交的拖放 |
| 發射台未點火 | 跟隨可縮放 | 進成果頁再返回，維持跟隨與倍率；明確點火 |
| 運行中上升／滑行 | 可縮放，保持原 running 狀態 | 操作引擎／控制，時間繼續前進 |
| 已暫停飛行 | 可縮放，仍保持暫停 | 明確按繼續才推進時間 |
| 分離過渡及分離後 | 上級為跟隨目標，兩級位置保持一致物理尺度 | 上級點火，觀察下級獨立運動；縮放不改分離時間 |
| 墜毀／離開範圍及返回工廠 | 可檢視既有可用視角 | 合法返回組裝，保留已記錄成果 |
| 成果檢查及返回編輯 | 可縮放檢查的成果 | 返回原視角；正式提交仍由使用者明確操作 |
| 已提交 review／committed | 可縮放與旋轉，編輯仍鎖定 | 可繼續檢視，不能藉手勢改答案或重開作答 |
| frozen pending／可重試提交 | 可用的成果鏡頭可縮放 | 同一份 pending bytes 重試，分數及答案不變 |
| render lost 或 startup 無可用場景 | 不接受相機輸入 | 依既有恢復／技術處理；恢復後以新手勢繼續 |

靜止情境比較操作前後的正式狀態與 canonical payload，應完全一致。運行中情境另記錄合法經過時間，與同等模型時間的控制組比較；不能用「時間有前進」掩蓋手勢誤改油門、姿態、組裝或成果。

## 九 實作順序與階段出口

工作按依賴順序執行。每階段只在其出口條件通過後前進；發現失敗先修正該範圍，不同時擴大到其他美術或物理改動。

| 階段 | 工作 | 完成出口 |
|---|---|---|
| 0 基準與測試準備 | 重查最新來源及所有 zoom 呼叫處，保存四視角與分離前後的正常構圖；準備合法 production fixtures | 可重現目前跟隨倍率抵銷；有 source／package 測試入口及前後比較基準 |
| 1 修正鏡頭縮放 | 分離 baseDistance 與手動倍率，整理比例、投影及安全限制；先讓既有按鈕也走共用入口以便對照 | 1 倍維持正常構圖；2 倍真正放大；模型尺度不隨手動倍率改變；分離與接觸畫面通過 |
| 2 接入輸入與取消 | 多指資格及接管、wheel、touchpad 去重、鍵盤、每幀合併；更新對應測試 | 實際手勢有效；釋放／中斷後可以正常續作；正式組裝未被誤改 |
| 3 清理介面 | 移除設定區及三個按鈕、完成回正與簡短說明、更新焦點及舊測試 | 手機面板減少佔位；每種輸入都有縮放與回正方法；沒有殘留 DOM 引用 |
| 4 整合驗收 | 執行下列 source／package、宿主、生命周期及渲染回歸；檢視截圖及資源紀錄 | 所有必需自動化檢查通過，真機與 Moodle 未驗部分獨立列明 |
| 5 提交與發布 | 依測試過的實際 bytes 封裝、commit／push、更新原 Site、核對線上檔案 | 可追溯來源 SHA、套件 hash、部署版本與成功結果，主計劃記錄實際證據 |

建議按鏡頭、手勢、介面與整合形成可審查的提交；每個提交的呼叫者與對應測試須一致，不能先刪除按鈕卻留下仍依賴它的正式測試。發布僅發生在後續已獲授權的實作工作中，本次文件交付不觸發發布。

各宿主先記錄真正擁有捲動範圍的 window 或元素及 origin／sandbox，不把 parent 或 top 自動當作擁有者。T1–T3 沿用共用契約指定的兩個正常活動作宿主對照。任何跨來源部署須另驗其原生路徑或現有 adapter。

中央縮放時非擁有者位置保持不變；面板捲動時鏡頭與宿主保持不變；側帶滑動時只有實際宿主捲動。沿用契約的 1 CSS px 捨入容差，不接受中途來回跳動後最後回到原位作為通過。故障提示出現及 submitted／pending 狀態也需保持可用捲動入口。

## 十一 測試執行與證據管理

既有 `tools/rocket-space-mission-browser-regression.js` 已提供 `--gesture-zoom` 整合入口、`--gesture-zoom-only` 手機聚焦、`--gesture-core-hosts` 與 `--gesture-regressions-only` 分組；正式 full runner 也包含新情境。實際執行組別及來源前段續跑方式見主計劃 P50，不以可用參數冒充已執行整套。

本次會影響鏡頭、幾何投影及手勢，因此必跑新情境，以及既有 direct camera、camera memory、bottom-up assembly、分離真實尺度、碰撞與地表深度、向上望天空、向量比例、graphics recovery 及生命周期案例。先按階段執行聚焦案例，最後做一次完整的受影響組合；通過後只因新修改或明確未解問題重跑，避免無目的重複全套。

沿用七份已登記的 rocket Node tests；只有新增非平凡規則才增加對應小型測試。Node 無法代替可信輸入與實際投影驗證。`npm run check`、`npm run check:tests`、manifest 閉包及 `git diff --check` 都要記錄結果。新增正式 helper 或 test file 時更新登記，單純增加既有 runner 的情境則沿用原 owner。

提交後執行 `node tools/run-tests.js --base=<本輪基準SHA> --head=<實作SHA> --plan`，保存 affected selection；這是選取預覽，不是所列測試已執行的證據。Windows browser 操作沿用 production guide 的環境規則；若使用 Playwright CLI，明確使用 Git Bash，不使用 PATH 上的 WSL bash。

建議產出以下忽略版控的證據，正式摘要寫入主計劃：

## 十二 風險與處理優先次序

| 優先 | 風險 | 預防與發現方法 |
|---|---|---|
| 最高 | 縮放輸入導致零件誤裝、誤拆或已提交資料被改 | 正式模型只在既有合法放手流程提交；雙指接管取消預覽；G03–G05、D01–D04 |
| 高 | 跟隨模型自動縮放抵銷用戶倍率 | 正常距離與手動倍率分開；實際投影和固定 world scale 斷言 |
| 高 | 縮放令兩級尺度或近地位置重新錯位 | 凍結世界座標比對；分離、山坡、海面及發射台回歸 |
| 高 | 頁面、面板與相機同時移動 | 起點所有權及中央邊界；T0–T3 每步取樣；真機另驗 |
| 高 | Safari 或 touchpad 同時送兩套事件，倍率倍增 | 同次手勢固定事件來源，記錄事件序列並驗去重 |
| 中 | 失去 capture 後狀態卡住或殘留手指誤操作 | 原子接管、可重複清理、全部放開前阻擋；G05–G06 |
| 中 | 放大後可見零件與透明命中區錯位 | 同幀投影及 positionTargets；量度實際 CSS px 與可信拖放 |
| 中 | 每個事件重建場景造成卡頓或記憶體增加 | 合併畫面更新、既有細節快取、D06 資源與閒置檢查 |
| 中 | 無按鈕後不知道怎樣回正 | 空白雙點／雙擊、聚焦 Home 及簡短操作說明；G09–G10 |

阻止發布的問題包括正式資料改動、中央縮放與宿主競爭、分離或穿地回歸、失去控制後無法續作、來源與封裝不一致。真機或實際 Moodle 尚未驗時必須列明範圍，不能將 package-ready 等同 Moodle-ready。

## 十三 發布與回退

後續實作完成後，先保存本輪基準與實作 SHA，再由通過測試的 runtime bytes 建立正式套件。重新核對 manifest、ZIP 解壓內容、來源 hash 與 Site dist；文檔提交不應混淆實際已測試的 runtime 版本。

原 Site 與原 owner-private 權限保持，部署至原網址。記錄 source commit、package SHA、Site version、deployment ID 及明確成功狀態。發布後比對線上入口、interaction、scene、main、styles 與 build-info，並檢查原網址能開啟。

若新版發生阻止使用的問題，回到部署前已核對的上一個成功 Site 版本與套件；來源以撤回本次相關提交處理，不整個覆蓋成早期版本，避免丟失 P49 圖像恢復及其他既有修正。回退也要重新確認部署成功及實際線上檔案。
