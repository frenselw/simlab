# 小小航天家飛行事件與分段載入計劃

2026-11-12。分支 `codex/rocket-explorer-flight-and-loading`，以 `origin/main` 的 `de3e055` 為基準。

本輪先定實作與驗收方案。範圍是 `rocket-side-booster-lab` 的飛行事件列、工廠啟動、地形準備與視覺補載。產品範圍見[小小航天家現行計劃](42-rocket-explorer-workbench.md)。沿用[共用設計](00-shared-platform-and-style.md)及[製作與驗證契約](../docs/simulation-scorm-production-guide.md#scope-and-shared-cores)。本工具供自由探索，評核風險、rubric、提交、答案快照及 Moodle 續作皆不適用。事件紀錄是本次試飛的暫態介面資料。

## 1. 飛行事件列

位置依[桌面效果圖](../output/mockups/flight-events-2026-11-12/desktop.png)、[iPad 效果圖](../output/mockups/flight-events-2026-11-12/ipad-landscape.png)和[手機效果圖](../output/mockups/flight-events-2026-11-12/phone-portrait.png)。在控制區現有近地點、遠地點及 T+ 讀數下方加入「飛行事件」，油門及轉向控制緊接其後。最新事件用淡青底和粗體，發生時刻與目前 T+ 分開。效果圖中的其他飛行數值及按鈕狀態是示意，介面以正式模型輸出為準。

| 尺寸 | 預設 | 操作 |
| --- | --- | --- |
| 桌面寬版 | 顯示最近兩件，最新在上 | 兩列直接閱讀 |
| iPad（直向或橫向） | 一列顯示最新事件 | 點整列展開上一件，再點收合 |
| 手機（直向或橫向） | 在舞台下方顯示一條全寬事件列 | 同樣點整列展開，觸控目標至少 44 px |

桌面寬版的實作基準是視窗至少 1200 CSS px，且沒有粗指標（`any-pointer: coarse`）。觸控裝置及較窄視窗採收合版，因此 iPad 接上觸控板時仍有觸控版的預設。事件列跟隨控制區排版，保留舞台的拖動、縮放與捲頁把手。展開向下增加一列，短螢幕由原控制面板捲動，驗證油門及方向控制仍可到達。

沒有事件時隱藏，只有一件時只顯示一列，第二件出現後才提供展開。相同版型內，增加事件不會自行收合或移動焦點。收合控件支援鍵盤及 `aria-expanded`，新事件以 `aria-live="polite"` 提示一次，T+ 更新不觸發事件朗讀。

### 事件來源及時間

在既有 `RocketRuntime.Controller` 保留最近兩筆 `{type, t, body}`。從成功的 `command` 及每個實際推進的物理步比較前後狀態。現有 `advanceFrame` 逐次執行 `tick(request, 1)`，在這個邊界擷取事件，避免同一畫面間的高倍速轉換被合併。若有多步的呼叫，仍須逐步觀察，不能靠批次首尾猜測中間事件。先檢查既有命令、步進及測試呼叫點，再決定是否需要在模型步進出口補一個通知點。

| 事件 | 採用的狀態轉換 |
| --- | --- |
| 點火、離地 | 本體引擎從關閉到點燃，以及主體從發射台到飛行 |
| 助推器燃盡、助推器分離 | `burning → spent` 與實際變為 `jettisoned`，提早分離也如實記錄 |
| 級間分離、太空艙分離 | 實際切換到上級，以及太空艙進入分艙狀態 |
| 減速傘／主傘開始張開 | 太空艙分別進入 `drogue-opening`／`main-opening`。用現有 `chute.since` 作為開始時刻 |
| 着陸、撞地、隔熱防護耗盡 | 本體第一次進入對應結果狀態，以既有判定區分結果 |

時間採該命令或物理轉換發生時的任務模擬時間，顯示至小數一位，例如「T+ 61.3 s　助推器燃盡」。物理步會就地更新狀態，因此步進前只複製事件判定所需欄位。若轉換的時間會在同一步被覆蓋（例如二級觸地後同步任務時鐘），在轉換處保留實際時刻。同一物理步有多件事件時，按實際發生順序加入，時間相同時仍維持固定順序。太空艙與二級事件標清對象，切換操控本體時仍顯示同一次試飛的最近兩件。暫停、重繪、失敗命令及切換鏡頭不產生事件。返回工廠、重新試飛或刷新時清空本次紀錄。

## 2. 先開放組裝，再準備發射

目前 `scene-art.js` 的頂層 `Promise.all` 等待兩份高度圖、地形及貼圖，之後 `main.js` 才完成場景和拖放接合。公開版曾量得首幀約 22.6、45 和 71.8 秒，其中一次首次下載約 29.7 MB。兩份 gzip 高度資料佔約 22.3 MB。這些是個別桌面測量，供同條件重測時核對。

把 `RocketScene` 初始化分成兩段，沿用同一個畫布、控制器、火箭模型及既有拖放。第一段只建立工廠鏡頭、組裝平台、零件、燈光與拾取，讓第一次工廠畫面可操作。把 `scene-art.js` 頂層的大型資產等待移入明確的背景載入流程，工廠可操作後開始兩份高度圖及最低限度飛行場景的載入。之後把飛行環境接上原場景，保留學生已放上的零件和正在使用的組裝視角。實作時逐一檢查建構、繪製、調整視窗及 WebGL 恢復對飛行資產的存取，確保工廠階段可獨立運行。

| 準備狀態 | 學生可操作 | 前往發射台 |
| --- | --- | --- |
| 工廠可用，背景載入／驗證中 | 拖放、取出、轉動及縮放 | 停用，附近顯示「正在準備飛行地形」 |
| 全球及發射區高度圖已驗證，基礎飛行場景已接好 | 繼續組裝或前往發射台 | 火箭結構完整且圖像可用時開放，由學生點擊 |
| 必要資產下載或驗證失敗 | 繼續組裝，點「重試載入地形」 | 保持停用，保留現有火箭和工廠畫面 |

在 `surface.js` 延續既有 HTTP、gzip、尺寸及數值檢查。兩份高度圖先解壓並驗證，整批成功才一同成為本次飛行的高度來源。併發呼叫共享同一批請求。失敗時結束該批未完成的工作並清除失敗中的 Promise，才開放重試，舊請求的回應不能覆寫新批結果。這可避免目前失敗後重用已拒絕的 Promise。重試只重新準備地形及必要場景。現有前往發射台的按鈕與 `launch` 命令都要查同一個準備狀態，防止快捷路徑在高度資料未就緒時進入飛行。

## 3. 依視角補載純視覺資源

| 資源 | 載入時機及責任 |
| --- | --- |
| 工廠和零件的程序式模型與必要模組 | 工廠首畫面 |
| 全球及發射區高度圖、基礎地形網格 `terrain.bin`／`global/coarse.bin`、基本地球場景所需資源 | 工廠可用後背景準備。兩份高度資料及基礎飛行場景驗證完成才開放發射 |
| `regional-surface.png` 的區域地表細節 | 飛行視角第一次需要發射區細節時請求。等待時用既有基礎地形與顏色。shader 只在貼圖就緒後採樣 |
| `global-detail/index.json` 與精細坡面瓦片 | 進入需要全球地表細節的視角後，沿用 `global-terrain.js`／`terrain-detail.js` 的可見區、距離及既有前方預讀選取 |

沿用[全球地形載入與快取契約](42-rocket-explorer-streamed-global-detail.md)，維持同一個瓦片載入管道及既有 4 active／6 cache／2 pending 預算。鏡頭離開時取消過期請求，遲到回應只可寫入仍有效的目標。精細貼圖逾時、404 或解碼失敗時，基礎地形繼續顯示，不能鎖住發射或暫停飛行。現有中繼地形部署沿用自己的配置與相同視覺降級規則。

整次飛行的離地高度、碰撞、降落傘判定、觸地及停定位置都取自已驗證的 `RocketSurface`。補載只更新材質、法線或視覺網格。飛船接地附近的視覺面仍以權威高度貼合。驗收時在固定狀態前後比較碰撞高度、離地高度與飛船位置，並目視低空和着陸畫面，避免視覺地面跳動。

## 實作次序與驗收

1. **事件列。** 接合 `ui-runtime.js`、`main.js`、`index.html` 與 `styles.css`。沿用 `runtime.test.js` 驗證命令、步進、同幀多事件、跨本體、去重及清空。在正式瀏覽器流程實際點火、分離與開傘，核對顯示的事件及時間等於模型轉換。以 1280×900 桌面、1194×834 與 834×1194 觸控 iPad、390×844 與 320×500 手機檢查預設、展開、按鍵焦點、短屏捲動及全螢幕。保留三版截圖。
2. **工廠先行及重試。** 接合 `scene.js`、`scene-art.js`、`surface.js` 與發射入口。在來源及解壓 standalone 故意攔住其中一份及兩份高度圖，執行可信拖放，驗證組裝可先完成、按鈕與命令皆阻止提前發射。測試下載失敗、壞 gzip 或格點驗證失敗後重試，逐件核對火箭仍在，成功後可進發射台和點火。測同時重試、刷新回空白工廠及 WebGL 恢復。
3. **按視角補載及整合。** 沿用現有 terrain／world browser owners 驗證工廠階段不請求精細貼圖，視角需要時才載入。測慢回應、轉鏡取消、細節載入失敗及恢復，檢查基礎地面可用、地形快取在預算內，並比較補載前後的飛船狀態、碰撞高度與畫面。涵蓋發射區、區域邊界、全球視角及至少一次完整返航。
4. **效能與交付證據。** 在同機、同視窗和相同限速下，用新瀏覽器設定檔對照基準與新版本，各三次記錄首個可組裝畫面、可發射時刻及兩個時刻前已完成的下載量。功能門檻是兩份高度圖及精細貼圖可保持未完成，學生仍能實際裝入零件。也要在下載及解壓過程實際拖放，檢查長時間的主執行緒阻塞，再決定是否需要將解碼分批。視覺補載未完成仍可在基礎場景起飛。沿用已登記的 Node 及 browser owners，若新增測試或 runtime 檔案，更新 `tools/test-registry.js` 或 `assets.json`。跑 `check:tests`，提交後保留 affected selection preview，重建並驗證 `output/packages/rocket-explorer-standalone.zip` 與 Pages 產物。來源、ZIP、Pages、實體裝置的結果分開記錄。

## 實作記錄

- 飛行控制區的事件列可隨面板捲動，短橫向畫面展開後仍可捲至油門及轉向。物理步直接回報開傘、觸地及隔熱耗盡的時刻，並在同步時鐘前記住二級觸地時間。單級火箭分艙後，剩餘本體標為核心級。
- 工廠使用原有畫布、拖放和火箭模型。地形尚未就緒時，發射與全景／軌道鏡頭暫停開放。驗證失敗後重新請求高度圖，原組裝、鏡頭和同一個 WebGL 場景保留。全球粗網格法線、區域網格及接地索引分批建立，讓瀏覽器在準備期間處理輸入。
- 補載的區域材質及全球坡面瓦片維持既有地形資料和瓦片預算。區域材質請求在離開區域或鏡頭朝向天空時取消。全球地形中，網格可以先顯示，坡面資料就緒後再更新光照。子代理與基準逐位元組比較 49 個區域網格及全球粗網格，100 個區域網格地面高度取樣相同。

### 冷啟動對照

同機 Chromium、390×844 觸控模擬，每次用新設定檔及冷快取，限速 2 MiB/s、延遲 70 ms。數字為各三次的中位數。下載量採量測當時已完成的 HTTP 回應 body，含頁面與共用程式。

| 時點 | 基準 `de3e055` | 改版 |
| --- | ---: | ---: |
| 工廠可組裝 | 17.39 秒／33.02 MB | 1.83 秒／2.11 MB |
| 地形準備完成 | 17.39 秒／33.02 MB | 15.29 秒／28.75 MB |

初版分段載入在準備完成前曾出現 459–498 ms 的主執行緒工作。分批建立網格後，三次各自的最長工作為 189、193、205 ms，工廠首幀均在兩份高度圖完成前。原始資料見[冷啟動對照](../output/reports/rocket-explorer-flight-loading-benchmark.json)。
