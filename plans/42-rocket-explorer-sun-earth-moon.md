# 小小航天家｜日地月運動、光照與天空觀測

2026-11-10 建立計劃，首版實作與驗證見文末。適用於 [《小小航天家：火箭升空與返航》](42-rocket-explorer-workbench.md)（`sim/rocket-side-booster-lab/`）。

## 1. 學習目標與實作範圍

- 從飛船切換到「望天空」，可以在正確方向看到太陽和月球。畫面反映觀測位置、鏡頭視野和地球遮擋。從全景可觀察地球日夜交界和飛船進出地影。
- 以同一個任務時鐘表現三種週期。地球自轉改變同一地點一天內的太陽方位。地球公轉配合地軸傾斜，改變不同季節的太陽高度、日照分布及晝夜長短。月球公轉改變月球方位和月相。地球與月球的位置取自同一套天文資料，月相由日、月、觀測者的相對位置算出。 [NASA 地球自轉與公轉](https://science.nasa.gov/earth/facts/) · [NASA 月相](https://science.nasa.gov/moon/moon-phases/)
- 首版採地球固定的飛行與地圖座標，將日月方向轉入這個座標系。地表仍是飛船、發射台、地形和接地的共同基準。飛行畫面用日月位置和光照呈現三種運動的觀測效果。飛行指南明示「以地面為參考觀看天空，飛行及返航採簡化模型」。 [固定地形座標的原有決定](42-rocket-explorer-visual-consistency.md#3-基礎決定採用一致的固定地球模型)
- 工程邊界包括獨立探索版的天空、光照、觀測日期及顯示。完整旋轉地球飛行力學、日月引力攝動、日月食、導航級星曆和太陽系全景另屬獨立課題。既有《火箭工廠：發射入軌》是另一個活動。

沿用 [共用版面與互動規則](00-shared-platform-and-style.md) 及 [製作與驗證規約](../docs/simulation-scorm-production-guide.md)。這是非評核探索工具，評分、提交、信任等級、答案快照及 Moodle 閘門均為 N/A。

## 2. 日期、時間與操作

| 階段 | 操作與時間行為 |
| --- | --- |
| 工廠 | 在現有控制面板下方放收合的「天空觀測時間」，可編輯 2026 年的 UTC 日期及時間（分鐘精度）。預設 2026-03-20 20:00 UTC，發射區接近正午，方便初次使用。日期、時間用原生欄位及明確標籤，錯誤就地說明。 |
| 待發射 | 按現有進入待發射流程鎖定觀測起點。可在點火前切換到「望天空」。要改日期可返回工廠，火箭設計隨現行流程保留。 |
| 飛行／滑行／返航 | `觀測時間 = 起點 UTC + 主任務 flight.t`。主任務時間同時供太空艙、二級和地景使用。倍速按實際積分推進量，暫停、調鏡、切換操控對象和 WebGL 恢復皆使用同一時刻。 |
| 結束／重新開始 | 任務結束後停在最後時刻，仍可轉鏡。返回工廠保留本頁選擇，重新整理回預設。只在記憶體保存設定。 |

現有 `T+` 繼續顯示飛行時間。觀測 UTC 放在飛行面板的次要讀數，無需逐幀讀屏公告，保留手機油門與轉向盤的首要位置及原有捲動區。輸入以 UTC 組合和校驗，不依賴裝置時區、時鐘或夏令時間。保留現有 7 日飛行上限，四季及完整月相比較透過不同出發日期進行。飛行指南可提供同一 UTC 時刻的六月／十二月對照，以及四個主要月相的日期。 [現有飛行時間限制](../sim/rocket-side-booster-lab/model.js#L65) · [2026 年主要月相資料](https://aa.usno.navy.mil/calculated/moon/phases?year=2026)

## 3. 天文資料與座標

### 本地資料

1. 實作先取一小段 JPL Horizons 樣本，核對欄名、座標系、單位及時間。候選查詢用太陽 `10`、月球 `301`、地心 `500@399`，取 `OBSERVER` 的無折射視赤經／赤緯和距離（`QUANTITIES=2,20`，角度用十進位度數、距離用 km、時間用 UT 零時區）。輸出須確證是當日真赤道／春分點基準。地心方位加上觀測者視差後，另用地面站的直接查詢校驗。 [JPL Horizons API](https://ssd-api.jpl.nasa.gov/doc/horizons.html) · [Horizons 欄位及參考系說明](https://ssd.jpl.nasa.gov/horizons/manual.html)
2. 樣本通過後，匯出 2026-01-01 00:00 到 2027-01-08 00:00 UTC，每 6 小時一筆（首尾共 1,489 筆）。額外一週讓 12 月 31 日深夜啟動的任務仍有完整插值區間。離線把赤經、赤緯和距離轉成等距取樣的直角向量，以整數 km 儲存。重建工具驗證時間格、欄數、有限值及日月距離範圍，記錄查詢參數、星曆版本和資料雜湊。
3. 執行時讀取同源的本地星曆檔，按 UTC 找相鄰兩筆並線性插值。在直角座標做運算，跨越赤經 360° 也連續。資料及天文運算模組都列入 `assets.json`，目標資料原始大小不超過 128 KiB。Horizons 查詢及重建工具只在開發端使用。資料載入或驗證失敗時明示「天文資料暫不可用」，停用日期選擇和日月圓盤，沿用現有固定光照，飛行可繼續。

### 三個座標步驟

1. 地心星曆中的日月位置已隨地球和月球的公轉變化。依 USNO 的近似格林威治恆星時，用 UTC 近似 UT1，將同一時刻的兩個地心向量繞真地理北軸轉入地球固定座標。標準赤道直角座標以 `Rz(-θ)` 轉換，格林威治往東為正。驗證赤經等於恆星時、赤緯為零的天體落在格林威治赤道上空，且固定天體隨時間向西移動。 [USNO 恆星時](https://aa.usno.navy.mil/faq/GAST) · [USNO 地平座標](https://aa.usno.navy.mil/faq/alt_az)
2. 重用 `surface.js` 現有發射場經緯度和地理基底，取地球固定向量在東、上、北三個軸上的分量。世界地圖和現有飛行狀態沿用此基底。把場景中真北軸映射到北緯 90° 作校驗，避免把發射場上方的場景 Y 軸用作自轉軸。地圖既有的 `.7` 弧度素材對位角留在材質／地形對位層。 [地理基底](../sim/rocket-side-booster-lab/surface.js#L16)
3. `scene.js` 按鏡頭採用現有世界到畫面的轉換。全景／軌道正視使用地心的場景基底，跟隨鏡頭則沿用以飛船位置建立的局部垂直轉換。太陽方向、月球方向、遮擋與畫面都用相同轉換。全景以外部鏡頭觀察；跟隨以現有第三人稱相機觀察。從實際相機相對地球中心的位移，按當前模式的尺度還原觀測位置。光照計算仍取每艘飛船自己的模型位置。

## 4. 光照、遮擋與畫面

| 模組 | 實作 |
| --- | --- |
| 天文運算 | 新增一個可由 Node 驗證的純運算模組，輸出地球固定座標的日月位置、從觀測者看出去的單位方向及角半徑。以 `天體位置 − 觀測者位置` 算視線，統一使用 km；月球視差由幾何自然得到。運算放在畫面更新，飛行積分每小步無需查表。 |
| 光照 | 把 `lighting.js` 的 `solar()` 改為接收同一個世界太陽方向，逐個遷移既有呼叫點。地球、海陸、雲層、大氣邊緣、森林和飛船共用此方向。保留現有黃昏混合及地影邏輯。地面日照用方向與局部垂直的夾角，飛船直射光用其位置是否在地影內；測試同一幀一艘受光、另一艘在陰影的情況。季節效果以光照角度和時長呈現。 |
| 望天空鏡頭 | 現有跟隨鏡頭一直對準火箭，低空防穿地會進一步限制向上視角。於現有鏡頭控制區加「望天空」，沿用跟隨鏡頭的安全位置，將拖動改為原地轉頭，從地平線可望到天頂。以既有拖動手勢及鍵盤方向鍵操作，鏡頭按鈕可回到原本的跟隨構圖，切換只影響視角。短屏保留 44px 操作目標和原有捲動區。 |
| 天空 | 優先在現有天空 shader 加兩個按視角大小繪製的圓盤，沿用天空 pass 和前景深度順序，避免把日月的真實距離放進相機裁切範圍。圓盤入視野才畫。白晝月球降低對比度，太空背景保留明暗面。太陽可有輕微光暈，亮面位置須同地景受光一致。裝飾星空以同一恆星角轉向，保持其示意性。 |
| 月相 | 用「月球指向太陽」與「月球指向觀測者」的單位向量點積求受光比例 `(1 + dot) / 2`。圓盤逐像素按可見球面法線與日光方向着色，亮邊朝向天空中太陽投影，鏡頭轉動時亮邊亦跟正確方向走。月相受光幾何和被地球擋住是兩項獨立判斷。 |
| 遮擋 | 在天空 shader 以觀測位置及每條圓盤視線測試是否先交地球球體。保留地平線上升／下沉時的部分圓盤，地形由既有畫面深度遮擋。高空觀測者可看見位於本地水平線以下、仍高於地球邊緣的天體。星點層須遮去落在可見日月圓盤內的點。大氣折射與日月食可留待獨立實作。 |

優先重用 [固定太陽與地影程式](../sim/rocket-side-booster-lab/lighting.js) 及 [既有天空材質](../sim/rocket-side-booster-lab/scene-art.js)。在實作中將度數、弧度、米、km 及顯示尺度隔離在輸入／座標邊界。穩定更新同一組 uniform，不在每幀重建材質、天空幾何或貼圖。Context 恢復由當前 UTC 與相機重新填入 uniform。

## 5. 實作次序與影響範圍

1. **先驗證資料和座標。** 抽查兩顆天體的輸出基底，建立本地資料及純運算測試。先在地面、400 km 軌道及全景觀測位置對比日月方位，再接畫面。
2. **接任務時鐘與光照。** `index.html`／`styles.css` 增加日期時間欄位及次要讀數，`main.js` 把主任務 UTC 傳給 `scene.js`。更新 `lighting.js` 及調用它的測試。先確認同地點日間、黃昏、夜間的像素和飛船地影，再加入圓盤。
3. **接天空和月相。** 在 `scene.js`／`scene-art.js` 加觀測者轉換、圓盤、相位和遮擋。沿用 `interaction.js` 的鏡頭手勢，把「望天空」接到現有鏡頭選擇。完成跟隨／全景對照、鏡頭轉動、日月同時入鏡和接地視覺回歸。
4. **驗證交付。** 更新 `assets.json` 與 `tools/test-registry.js`，重用 `tools/rocket-side-booster-browser-regression.js` 的 source／standalone 執行器和現有 world 測試。按 [測試登記規約](../docs/simulation-scorm-production-guide.md#test-registration-for-new-simulations) 記錄 `check:tests` 和提交後的 selection preview，依 [清理規約](../docs/simulation-scorm-production-guide.md#generated-output-and-cleanup) 只保留必要證據及交付物。

主要改動集中於探索版的 UI 和渲染。光照時間與飛行輸入分離。需跨不同日期重跑同一發射、入軌、分離和返航腳本，比對飛行狀態及接地結果，以證明渲染設定沒有流入飛行運算。若要令地面與飛船真正按自轉互動，下一份物理計劃須先定義三維地心慣性狀態、地球固定地形、發射初速度、大氣相對速度、地面相對速度和接地共轉，再按這個基礎重測所有飛行階段。

## 6. 驗收清單

以下列出驗收條件。實際執行的範圍和結果見第 7 節。

| 驗證 | 通過條件 |
| --- | --- |
| 星曆與時間 | 驗證首尾、跨日、跨年、起點範圍及七日餘量；同一輸入在不同裝置時區相同。挑選獨立、未用作取樣節點的 Horizons 時刻及幾個地面站，以無折射視線角距量誤差（首版目標太陽 ≤0.1°、月球 ≤0.2°）。用同一 UTC 的獨立資料核對月相受光比例，目標誤差 ≤2 個百分點。 |
| 日夜與季節 | 同一地點按 UTC 前進能從日出轉到夜間，日夜分界連續移動。用固定北半球位置比較六月與十二月，六月正午太陽更高、白晝更長。畫面需檢查地景與大氣像素，不能只讀 uniform。 |
| 日月與鏡頭 | 有案例可同時看見日月，且日間可見月球。從待發射和在軌狀態都能轉向天頂，再切回原有跟隨構圖。驗證新月、上弦、滿月、下弦的亮面方向及比例。檢查天體在視野外、在地球背後、掠過地球邊緣、被前景地形遮擋。低空、400 km、全景各拍對照圖。400 km 有一組地面已入夜而飛船仍受照。 |
| 任務操作 | 用實際執行的 1×、100×、1000× 滑行核對觀測 UTC 與 `flight.t`。暫停轉鏡、換艙、觸地、恢復 WebGL、返回工廠、重新整理和年末起飛皆有可重現測試；故障案例驗證沒有天文資料也能操作飛船。 |
| 手機與效能 | Source 及解壓 ZIP 跑 320px 短屏、390px 手機及橫屏、平板和桌面代表案例。真觸控檢查日期操作、天空拖動、捲動區及 fullscreen。對照同機基準記錄 draw calls、貼圖用量和幀時間。目標沿用天空 pass，無新高解析貼圖；以實體手機 Safari／Chrome 記錄畫面與性能，桌面模擬結果單列。 |
| 套件 | 執行 `npm run check`、`npm run check:tests`、相關 Node／browser 測試與 `npm run package:rocket-explorer`。確認 source／解壓 ZIP 檔案一致、無外部星曆請求、無缺失資源或 WebGL 錯誤。紀錄到 [package-ready 閘門](../docs/simulation-scorm-production-guide.md#package-ready-checks)；實體裝置證據單列。 |

先完成第 1、2 階段即可驗證最關鍵的座標與日夜效果。真正影響首版工作量的是視角轉換、近地平線遮擋，以及本地資料和手機渲染的驗證。
