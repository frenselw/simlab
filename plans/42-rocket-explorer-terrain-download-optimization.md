## 2. 容量定義與目標

全篇使用十進位 MB，`1 MB = 1,000,000 bytes`。5 MB 是上限目標，不是必須用盡的額度。

### 2.1 必須一併計算的內容

地形容量包含全球及發射區高度、近場補丁、海陸遮罩、地形網格、地理索引、地球及雲層貼圖、法線及地表材質、相關解碼器與 WASM，以及仍保留的內嵌 fallback 資料。不能只報兩份高度檔的大小，也不能把必載資料改名為背景下載後排除。

同時另列整個活動的 HTML、一般 JS、Three.js、音效及其他資產，清楚分開「地形相關流量」和「整頁總流量」。本計劃的 5 MB 指地形相關部分，並不宣稱整個網站已少於 5 MB。

| 測量情境 | 目標與判定 |
|---|---|
| 冷快取，工廠可拖放 | 不等待全球或區域高度。記錄到此刻已傳輸的全部資產及互動時間 |
| 冷快取，首次可發射且起始畫面穩定 | 地形相關內容力求不高於 4.5 MB，上限 5 MB |
| 預設發射區完整一次升空、分離、返航及同區移動鏡頭 | 同一頁面累計地形流量以不高於 5 MB 為驗收目標，測到觸地後 30 秒，不以剛解鎖發射的數字代替 |
| 遠距離探索新地區 | 基礎全球資料不重載；按實際可見範圍補載，報告每區新增量及累計量。無限探索不宣稱固定 5 MB |
| 同區反覆切換鏡頭及第二次試飛 | 有效快取中的相同資料不再下載；記錄驅逐後重載，避免來回移動產生大量流量 |
| 失敗、重試及取消 | 額外記錄已收到的部分資料和重試量，不能只加總成功請求 |

成功路徑以瀏覽器實測壓縮後 body bytes 為主，另記 HTTP 傳輸量、快取命中及伺服器壓縮行為。中斷請求用 CDP 或伺服器計數補足，不能把缺少 Resource Timing 數字當作零流量。ZIP 大小、原始檔大小、解碼後記憶體及 GPU 貼圖大小分開報告。

### 2.2 首輪原型配置

| 項目 | 預算 | 依據及待驗證事項 |
|---|---:|---|
| 全球及發射區 LERC 高度，含海陸有效遮罩 | 約 3.331 MB | 全球 100 m、區域 10 m 格點誤差候選，實測 3,330,590 bytes；不是已通過的畫質設定 |
| 約 60 × 60 km 近場原精度資料 | 約 0.28 MB | 既有裁切研究的量級。須按實際發射場重新固定範圍、邊帶和壓縮結果 |
| 4K 地球色彩及雲層 | 約 0.24 MB | 現有圖像已很小，優先保留 |
| 該次飛行實際需要的法線／材質細節 | 0.50–0.70 MB | 小瓦片、父層 fallback、同區重用；須實測完整返航累計量 |
| 解碼器、WASM、索引、邊界及剩餘基礎資料 | 0.15–0.30 MB | 實際依賴、內嵌 fallback、地理資料和網格都計入，不假設為零 |
| 合計 | 約 4.50–4.85 MB | 留少量餘額給邊帶及格式開銷，未證明可在所有情境達成 |

若畫質與容量不能同時達標，先調整局部誤差分配、重複資料及可見範圍補載。不得悄悄放寬為 8–10 MB，也不得把必要的山形或碰撞資料刪除來湊數。仍不達標時記錄具體差額和畫面差異，交代實際限制。

### 3.2 格點壓縮與三角網的實測比較

研究固定來源 commit，使用 LERC 4.0.1、Delatin 0.2.0、meshoptimizer 0.25 及 gzip level 9。LERC 保留原空間取樣位置，誤差相對現有高度資料，並非相對測量真值。

| 候選 | 高度資料量 | 解讀 |
|---|---:|---|
| LERC，區域 10 m／全球 100 m | 3,330,590 bytes | 首輪容量原型，全球近地畫質及誤差仍須檢查 |
| LERC，區域 10 m／全球 50 m | 4,185,547 bytes | 較嚴格全球候選，加入其餘資產後可能超出預算 |
| 三角網，區域 20 m／全球 100 m，meshopt + gzip | 3,182,445 bytes | 未計遮罩、分塊接縫、層級、法線及 metadata，不能直接宣稱勝出 |
| 單獨區域，5 m 的 LERC／三角網 | 2,799,932／5,586,361 bytes | 誤差要求較小時，三角網不一定更省 |

已逐點驗證 LERC 的有效陸地格點誤差及海陸 mask，已驗證 meshopt 頂點與三角形 round-trip。三角網全圖誤差由生成器檢查，另在一個 513 × 513 山區樣本作獨立重建驗證。全圖矩形三角網不等於可直接部署的球面 LOD。

60 × 60 km 山區診斷樣本中，均勻降到約 469 m 格距的最大高度差約 119.5 m；20 m 誤差三角網和 10 m LERC 分別保住自己的格點誤差上限，但仍可見折面或光影變化。因此容量、高度誤差、山脊輪廓和法線必須分開驗收，不能只看平均誤差。

### 3.3 貼圖實測

- 區域 packed PNG 改為無損 WebP 可由 4.062 MB 降到 2.104 MB，但仍然太大，優先消除其與高度資料的重複。

## 4. 技術方案及依賴次序

### 4.1 高度傳輸用有界誤差壓縮，近場保留精度

先製作 LERC 候選，保留原格點位置及海陸遮罩。以區域 10 m／全球 100 m 為容量起點，並保留全球 50 m 對照樣本。100 m 是全域候選誤差上限，不代表所有地方偏差 100 m，也不直接批准它用於近地山脈。

發射場附近加入約 60 × 60 km 原精度補丁，優先涵蓋實際起飛、常見返航及近場鏡頭範圍。補丁範圍、原點、格距及邊帶固定在資料版本內。內區保留原值，外區用固定權重與區域場接合，沿用原海陸分類及發射台平整規則。測試補丁內、邊帶及外側，不能只有中心正確。

若山脊或特定海岸未通過驗收，針對出問題的地塊使用更小誤差或靜態殘差補丁，計入相同預算。這些碰撞修正必須在發射前載入及驗證，不隨鏡頭補載改寫。

先確認現有 GeoTIFF bundle 內的 LERC 能否解碼選定格式及在 Worker 運作。若它需要載入整個大型 bundle，則比較獨立本地 LERC 解碼器的實際 JS／WASM 傳輸及記憶體，選一條部署路徑。固定版本、授權及格式，不能同時保留兩套必載解碼器，也不依賴 CDN。

### 4.2 固定唯一碰撞高度

`surface.js` 繼續擁有同步 `heightAt`、`height`、`radius`、`clearance`、`isWater` 等介面。所有已驗證的全球、區域及近場層一起原子安裝，成功後才開放發射。

- 一次飛行從發射到着陸使用同一資料版本、相同插值及混合規則。
- 碰撞、AGL、降落傘、森林基底、觸地動畫及近地接觸網格均以此場為準。
- 視角、網路完成次序、快取驅逐及細節瓦片到達不能改變同一座標的物理高度。
- 影像細節只改變色彩或法線。視覺高精度網格若與權威高度不同，沿用並驗證現有接觸地面融合，近接觸處收斂至同一高度，不能使艙體浮空、穿地或落入看不見的山。
- 保持現有區域／全球接合，以及經度環繞、極區、海平面及海陸邊界行為。
- 解碼、版本、尺寸或校驗失敗時維持發射鎖定；不能用低精度 fallback 默默開始另一套物理。

發射後的法線或可選視覺細節失敗只影響細節層，既有地面及飛行繼續有效。已着陸後再補載、旋轉鏡頭或恢復 WebGL context，艙體和地面不得移位。

### 4.3 重用高度生成可見網格，取消重複全量資料

調整 `terrain.js`、`global-terrain.js` 及建置流程，使區域與全球基礎可見網格從已驗證高度取得頂點高度。優先沿用現有 patch、索引及鏡頭選區方式，只生成所需層級，不在啟動時生成整個高精度地球。

畫面細分先按高度誤差投影到螢幕的像素大小決定。首輪目標為山脊 ROI 的輪廓差不高於 1 CSS px；近場接觸區另受物理貼合限制。地球曲率也納入細分，不能只對平面 DEM 計算高度誤差。

沿用 `triangulate-terrain.py` 的建置經驗，但它現有的抽樣誤差及頂點數上限不等於嚴格全格點誤差保證。若原型需要誤差控制網格，先離線比較現有生成器與 Delatin；只有實測表明瀏覽器內動態生成有必要，才引入 Martini／RTIN。最終部署只保留一種需要的生成路徑。

處理相鄰層級共邊、球面接縫及切換漸變。skirts 可遮縫但不能代替正確邊界或改動海岸線。網格誤差與高度壓縮誤差分別計算，最後檢查合成畫面，不能讓兩項各自通過後相加超標。

當替代路徑通過畫質、互動及效能驗收後，從本活動的必載清單與套件移除被取代的 `terrain.bin`、`global/coarse.bin` 及其他重複幾何。刪檔前查所有引用與其他活動資產清單；共用或仍有消費者的檔案只解除本活動依賴。

### 4.4 區域材質從同一地表場生成

`regional-surface.png` 的高度 RG 改由與 `RocketSurface` 一致的區域／全球混合結果生成，保留量化方式、軸向及 shader 取樣。不能直接用未混合的區域高度替代。

森林密度 B 優先由既有固定 seed、緯度、高度及乾濕公式重建；海陸 A 由原遮罩生成。先驗證森林分布及海岸是否一致，必要時只保留無法重建的小型殘差。不能聲稱移除 RG 就自然省下整張 4 MB PNG。

把一次性生成放在 Worker 或既有分批初始化路徑，資料傳遞避免重複複製。繼續使用現有小型程序化岩石、草地及水面細節，座標綁定地球，鏡頭與時間變動不造成紋理滑動。遠距離適當淡出高頻細節，避免手機閃爍。

高度和法線保持資料紋理的色彩空間、過濾及精度設定；若解碼經過 canvas，驗證沒有 gamma、alpha premultiplication 或通道重採樣造成數值改變。4K 地球色圖及小型雲圖保留。

### 4.5 全球法線切成較小無損瓦片

先把現有 10° 法線瓦片切成 2.5° 子瓦片，沿用來源解析度。研究候選每片為 259 × 259，含共邊及濾波需要的邊界樣本。實際 UV、重疊寬度及經度接縫由生成器和 sampler 同步定義，逐像素驗證與舊資料一致。

延用 `global-terrain.js`／`terrain-detail.js` 的請求、取消、快取、漸入及 context restore 管理。幾何瓦片可繼續以較大區塊選取，法線用獨立子區座標對應，不必一對一綁定。

原有 4 個 active mesh、6 個 cache、2 個 pending 和 6 槽法線 atlas 不能原封不動視為新粒度的充分容量。小瓦片必須有完整低層 fallback，近景才選擇細節，槽位和記憶體改以實際解碼 bytes 及可見覆蓋率核定。禁止為填滿空洞而把父塊的 16 片一律下載。

同一請求管理者負責去重、有限預取、取消離開畫面的工作及版本檢查。優先載入螢幕佔比大、距離近、飛行方向即將可見的子片；低於畫面誤差門檻的不載。正常完整返航接近流量上限時，保留已有基礎層及接觸地面，停止非必要更細法線預取，並檢查此狀態仍符合畫質標準。

### 4.6 Sites 額外精細來源

GitHub Pages 與 ZIP 必須在沒有 relay 的情況下通過上述標準。Sites 的 Copernicus／COG 路徑屬額外視覺來源，其請求也計入 Sites 的實際流量。

現有 `precise-terrain-worker.js` 會讀取所選 overview 的整張 raster。改為根據需求計算 `window` 加取樣邊帶，同檔需求合併，使用適合的 overview，限制解碼快取並沿用取消訊號。驗證伺服器 Range、實際傳輸量、跨 1° 檔邊界及無 Range fallback，不能只看 HTTP 206 就當作已節省。

這項在靜態基礎方案達標後進行。不新增付費服務、帳號或外部依賴；精細來源失敗不得改變碰撞或阻止已有飛行。

## 5. 資料格式、驗證與載入狀態

### 5.1 版本與驗證邊界

在現有 `surface-data.js`／資產索引擴充需要的 metadata，不另建通用資料管理層。每組資料至少記錄版本、codec 版本、相對檔案路徑、壓縮長度、解碼型別及尺寸、軸向／原點／格距、單位與 offset、海陸／無資料語義、各層誤差、補丁邊界和 SHA-256。

生成時對原始輸入、壓縮輸出及解碼結果驗證。執行時先檢查允許的版本、尺寸、上限及下載內容，再解碼並檢查 mask、有限數值和範圍。不得依檔案自報的巨大尺寸任意配置記憶體。部署使用版本化檔名或內容識別，舊索引配新資料必須失敗而非混用。

保持同步物理 API 的穩定性。Worker 完成後先驗證所有必需層，再一次安裝；取消與重試使用現有批次識別，舊批次不得覆蓋新狀態。解碼中盡量只保留一份最終 uint16 陣列，釋放浮點臨時緩衝及 Worker 工作記憶體。保留原解析度的 LERC 基線仍約需 100.7 MB 高度陣列，須另外量測峰值；若實體 iPad 記憶體不合格，再評估分塊保留或局部誤差簡化，不能宣稱下載縮小已解決記憶體問題。

此表補充主計劃現有 `workshop → pad → ascent/coast → ended`，不增加評核狀態或可保存答案。

## 7. 驗收標準

### 7.1 資料及物理

1. 每個有效原格點對解碼場驗證誤差上限，海陸分類逐點一致。對插值位置、陡坡、峰頂、補丁邊帶及區域／全球過渡另測合成誤差，不能以隨機樣本最大值冒充全域上限。
2. 測試截斷、錯誤 hash、錯誤版本、巨大尺寸、無資料、海陸 bit、NaN／非法值、失敗重試、取消及過期 Worker 回覆。失敗不解鎖發射，合法未完成組裝仍可操作。
3. 同一資料版本及相同飛行輸入，在不同網路完成次序、鏡頭及快取狀態下，物理高度、接地時刻和結果一致。
4. 驗證地面、海面、坡地、近場補丁邊緣及遠地區着陸。保留現有 RCS 零油仍可轉向、返航引擎獨立耗油，以及總速率 19.99／20／20.01 m/s 的着陸門檻。
5. 新資料容許的地形差異與物理規則分開檢查。不得為通過測試而直接重錄所有期望值，必須解釋變化來自哪一層資料。

### 7.2 畫面

固定模擬時間、光照、鏡頭、地點、seed、viewport 及 DPR，在相同 renderer 比較基準與候選。離線 hillshade 只作診斷，不能替代模擬畫面。

| 固定場景 | 必查內容 |
|---|---|
| 發射台及附近山坡 | 原精度區、發射台貼地、森林根部、近場補丁過渡 |
| 低空山谷及側看山脊 | 峰頂、稜線、谷地不被抹平，沒有明顯階梯或新增規則格紋 |
| 喜馬拉雅及安第斯山區 | 全球山系輪廓、陰影細節、陡坡及遠近切換 |
| 海岸、島嶼及海陸邊界 | 無新裂縫、漏水、錯誤海陸及島嶼消失 |
| 區域外緣、日期變更線及極區 | 取樣方向、共邊和球面曲率 |
| 軌道／再入及 100–220 km 過渡 | 地球連續色彩、地平線、幾何／globe 切換無明顯跳變 |
| 無傘及開傘着陸後 | 接觸網格、補載、鏡頭旋轉及 context restore 均不造成漂移 |

記錄山脊 ROI 的輪廓位移最大值及 P95，首輪以 1 CSS px 為目標；另記法線角差及材質差異。不得以整張影像平均值掩蓋局部削峰、海岸錯位或接觸錯誤。壓縮高度可能改變法線，必要時保留小型法線細節，不能以整面模糊掩蓋。

人工並排檢查屬必要畫質證據，記錄具體可見差異及判斷。若全球 100 m 候選不符合上述場景，改用局部較嚴格誤差後重新量測總容量，不先宣布該設定可交付。

- 與 `a27d3ca` 使用相同裝置、瀏覽器及網路設定比較。每個關鍵情境至少三次冷載入，記錄中位數及最慢一次，不宣稱小樣本為可靠 P95。

### 實際格式及資產

最終採用多層格點預測及 gzip。每隔 32 格保留原高度，逐層用相鄰粗格點預測中間高度，再儲存量化差值。這套格式連同原海陸遮罩及近場精度補丁共 **3,258,951 bytes**，比研究階段的 LERC 3,330,590 bytes 候選更小，並且可以用原生 gzip 解壓及共用 JavaScript 解碼。Worker 在兩份資料均下載後解碼，將陣列轉移到主程式。瀏覽器以 HTTPS 或 localhost 執行時亦驗證壓縮檔 SHA-256。

|---|---:|
| 發射區高度，含近場補丁 | 1,780,950 bytes。有效陸地格點最大差 5 m，P95 4.6 m |

網格及法線共用兩個並行請求。只挑選視野內的法線子片，所選瓦片的壓縮資料合計上限為 450,000 bytes。Sites 保留現有 COG relay，Worker 只要求當前取樣視窗及插值邊帶。其實際 Range 流量仍受來源檔的壓縮區塊佈局影響。

GPT-6 Astra xhigh 審核 `60f7ee11` 時確認相鄰法線瓦片載入進度不同會出現直線光影接縫。已按共邊及角位的最低漸入比例平滑過渡，經度環繞亦使用同一規則。GPU 回歸案例覆蓋相鄰瓦片缺失及漸入未完成兩種情況。

已用 JavaScript 實際解碼逐格核對 17,947,263 個有效陸地格點及所有海陸分類。量測報告在 `output/reports/rocket-terrain-compact-point-check.json`。兩份完整高度陣列仍佔 100.7 MB，實體 iPad 與手機的解碼峰值及幀率留待真機測試。
