# 火箭模擬：地形光照與視覺連續性修復計劃

計劃日期：2026-10-25。2026-10-26 使用者已授權實作；下列診斷保留為原始基準，實作證據另記於第 9 節與活動計劃 P37。

本文件對應使用者最新的 1,182.5 km 高度截圖：大陸出現規則的大格明暗、地貌欠自然，並要求先分析、暫停寫程式。目標是保留卡通風格，讓地形依坡向自然受光，在近地能看出高低、在高空保持連續，並控制手機成本。

基準為火箭 worktree 的 `5b35204`，最近 runtime 修改為 `299c08e`（P36）。本輪只讀程式與資產、檢視使用者圖片、在記憶體計算法線差異；沒有更改 runtime、資產、飛行狀態或網站。本計劃修訂 P36 的美術方向；P36 的近地座標精度修正仍有獨立價值，不應連同錯誤光照一起撤銷。

活動的 assessment risk、rubric、phase/variant、權威 snapshot 和 SCORM 契約沿用[活動計劃](../plans/40-rocket-space-mission-lab.md)。本次改善屬顯示層；相關規則見[共同風格](../plans/00-shared-platform-and-style.md)及[製作指南](simulation-scorm-production-guide.md)。

## 1. 現況診斷

### 1.1 大格紋的主要來源：分塊法線被當成真實坡度

全球地形以 10° × 10° 分塊。`global-terrain.py` 將各塊的頂點串接，邊界座標雖然一致，索引仍各自獨立。P36 在 `global-terrain.js` 對這些幾何呼叫 `computeVertexNormals()`，因此邊界兩邊只用各自那邊的三角形計算方向。

同時，地形 shader 用 `1 + 8 × dot(網格法線 − 球面徑向, 太陽方向)` 放大坡面效果，再限制在 0.62–1.34。問題在於「網格法線 − 球面徑向」既包含真正山坡，也包含粗球面三角形、單側邊界平均及海岸細長三角形的誤差。將它整體乘八，會把地形分塊畫出來。

只讀計算的結果：

| 北美範圍：經度 −130° 至 −60°、緯度 20° 至 65° | 現有高度 | 在記憶體將高度全部設為零，保持原拓撲 |
|---|---:|---:|
| 同位置、不同頂點索引的比較對數 | 1,395 | 1,395 |
| 法線角差中位數 | 1.76° | 1.65° |
| 法線角差 p95 | 2.96° | 2.60° |
| 固定診斷光源下，明暗倍率差中位數 | 0.103 | 0.092 |
| 明暗倍率差 p95 | 0.312 | 0.290 |

診斷光源是正規化的 (−0.5, 0.3, 1)。這些數字是 shader 係數差，**不是截圖像素色差，也不是百分比的螢幕亮度差**。但零高度對照已證明：即使沒有山，現有算法也會製造明暗接縫。圖片的大格形狀與此缺陷相符；各圖層對實際畫面的貢獻，實作前仍須以固定鏡頭逐層開關核對。

Three.js 的法線平均依共用索引，而非自動尋找相同座標；單純再呼叫一次相同函數，不會修好跨塊邊界。[BufferGeometry 官方文件](https://threejs.org/docs/pages/BufferGeometry.html)。

### 1.2 場景有光，但地面沒有使用同一套受光方式

`scene.js` 已建立 HemisphereLight（1.65）、主 DirectionalLight（2.4）及補光（0.6）。問題不是完全沒有燈，而是陸地使用 `MeshBasicMaterial` 再插入自訂 shader；這個材質本身不受場景燈影響。[MeshBasicMaterial 官方文件](https://threejs.org/docs/pages/MeshBasicMaterial.html)。

因此，直接增加環境燈，不會自動令現有地面正確受光。火箭／建物與地球主材質的光源方向亦分別設定；必須核對世界座標與相機轉換，讓飛行場景的陽光來源一致。

環境補光主要令背光面仍保留色彩，坡面明暗主要由方向光產生；山遮住另一處形成的「投影」則是另一項計算。HemisphereLight 本身不產生投影。[HemisphereLight 官方文件](https://threejs.org/docs/pages/HemisphereLight.html)。

### 1.3 顏色內已經有方向性明暗，後來又疊加一層

- 全球生成器 `global-terrain.py` 已將固定方向的坡度明暗乘進 vertex color。
- 區域生成器 `bake-terrain.mjs` 先取全球顏色，再乘局部 `localShade`。
- 近地 `contact-ground.js` 從全球 `colorAt` 取得同一個已染明暗的顏色。
- P36 再疊加新的坡度放大與日夜光照。

結果是地表本色、歷史烘焙陰影、現在的陽光混在一起。即使改動陽光，顏色裡的舊暗部也不會跟著轉，容易造成髒色、不協調，以及不同層級明暗不同。

### 1.4 細節策略沒有對準要求

新增 128 × 128 隨機色斑與最多 81 個近地樹石，能提供某些移動參照，但不能代替正確坡面受光。隨機色斑容易顯得雜亂；規則格內散點不等於合理地貌。

大陸的千公里級大格不能直接歸因於這張小噪點圖；法線接縫有更直接證據。兩者應分開處理，不能只刪噪點便宣稱所有格紋已解決。

### 1.5 上次驗收的缺口

P36 檢查了發射台遮擋、近地丘陵明暗係數、區域與全球替換色差、資源上限，但沒有建立全球相鄰格／粗細 LOD 的法線連續性驗收。`terrainColorSeams` 的定量檢查聚焦發射區與全球接替；有遠景取樣，不等於已檢查整個大陸的格紋。

「明暗係數有變化」只能證明有明暗，不能證明明暗是合理山坡。「三角形與 draw calls 不超標」也不能證明畫面自然或手機流暢。這次必須補上直接對應使用者截圖的驗收。

## 2. 視覺目標

| 視角 | 應看到的結果 | 不應出現的結果 |
|---|---|---|
| 地面至約 2 km | 向陽坡偏暖、背光坡偏冷；山脊／山谷可分；發射台完整貼地 | 坡和平地同色、亂點遮住坡形、發射台切片 |
| 約 2–100 km | 山脈為連續大形，明暗順著坡向，遠山稍淡 | 每塊地一種亮度、過密三角形碎色、硬切方塊 |
| 約 100–1,500 km | 大陸底色連續、球體日夜自然；大型山脈有克制的起伏感 | 經緯棋盤、發射區三角補丁、巨大的假山陰影 |
| 異地下降 | 地形和少量合理地標固定在世界座標，能看出接近和橫移 | 花紋跟鏡頭移動、地標在眼前跳出／重新排列 |

卡通感主要來自簡潔配色、柔和的兩至三段明暗及適度幾何簡化。全球網格邊界不屬於風格元素。高空不能要求每座小山都很凸出：幾公里高的地貌，相對地球尺度本來就很小。

## 3. 建議方案與順序

### A. 先固定問題場景，逐層拆解

建立少量可重現的本地診斷畫面，固定地點、時間、鏡頭、曝光、DPR、品質級別。第一個場景就用使用者約 1,182.5 km 的北美視角，再加入近地丘陵和發射台。

依次比較：原畫面 → 關閉新增坡度倍率 → 純地色 → 純法線／單色受光 → 關閉雲與噪點。這些開關只用於診斷，不增加學生操作介面。記錄格紋在哪一步消失，避免同時改五個參數後無法判斷原因。

**完成條件：** 有同角度前後對照，能分清幾何／法線接縫、顏色接縫及雲層覆蓋；先不重新生成全部地形。

### B. 修正法線來源，先讓「平的球面」真正平順

採用同一個地理位置與高度場導出的受光法線，全球 coarse/fine、區域及近地地面共用相同規則。其概念是：球面徑向決定地球曲率，連續高度場的東西／南北坡度決定局部傾斜。

- 法線不能再由各塊各自的單側三角形平均決定；相同地理位置必須得到相同受光方向。
- 先重用現有 `Surface.heightAt` 高度來源及 normal attribute，原型以鄰近高度差求坡度；取樣範圍用實際距離，不能隨 tile ID 或 LOD 改變。
- 全球高度資料約 0.5°、局部約 1.875 km 間距：光照可呈現的細節有上限。取樣和濾波必須對應資料尺度，避免把高度格的折線重新畫成方格。局部與全球的取樣尺度應在銜接帶平滑過渡。
- 海岸、海陸 mask 切換、日期變更線及極區要專門處理：海面用徑向法線；海岸不能因取到海洋零高度便產生虛假的巨大斜坡；極區用穩定切平面方向。
- 法線在載入或既有地面重建時算一次，不在每幀遍歷整個地球。若實測載入計算造成長任務，改為離線烘焙相同法線，避免把成本轉移到手機首次開啟。
- 先做兩塊相鄰全球地形、粗細交界及一塊近地丘陵原型，通過後才套用所有資產。

不以增加大量多邊形掩蓋接縫，也不只焊接當前粗網格：後者仍未解決另外載入的 fine tile、海岸及近地網格。

**完成條件：** 零高度球面無格紋；共用位置法線一致；切換 LOD 不改變山坡明暗方向；不移動任何碰撞／顯示頂點。

### C. 分開本色與光照，建立一套受光模型

1. **地表本色**：草地、森林、沙地與岩地只保留低頻、低對比的地貌配色；移除顏色中的舊定向坡面陰影。全球與區域一起更新本色來源，近地 `colorAt` 隨之使用同一色場。
2. **陽光**：以同一太陽方向和修正後的法線計算漫反射。飛行場景的火箭、地面、建築、雲及大氣使用一致的方向；組裝頁的攝影棚照明獨立保留。
3. **天空與地面補光**：讓背光面保留較冷、較暗的色彩；補光依當地地表朝向及日夜狀態變化，不能用固定世界 Y 軸把另一半地球照錯。
4. **卡通化**：先用平滑明暗，再視需要做柔和色階。避免硬閾值和高對比面片。初始可用約 25–35% 補光、65–75% 陽光作日照下相對配比，這是調校起點，需看 linear color 與既有 ACES 曝光後的畫面，不是直接把燈強度照抄進去。
5. **起伏強調**：只有在正常漫反射仍不足時，才對「真正坡度分量」輕量放大，初始上限約 2 倍；大球面方向不放大。高空依投影尺寸減弱細節，不能把地球網格誤差再次放大。

優先整理現有共用 `terrainLighting`，保留目前必要的裁切、深度及近地精度處理，實現一套簡單的漫反射＋半球補光。直接把地面改成 Lambert 材質，也仍須解決法線、舊烘焙顏色和球面補光座標；不能把換材質當作完整修復。

本輪不靠提高曝光或增加全場環境燈掩蓋問題，也不引入 PBR／HDR 環境貼圖作為前提。

**完成條件：** 單色地形亦能辨認坡向；轉動測試太陽會交換向陽／背光面；底色沒有殘留的反方向陰影；轉鏡頭時光照仍固定在世界。

### D. 收斂地表細節，建立近遠景層次

先取消 P36 的全域白噪點乘色作為預設方案，暫停依靠格狀散佈樹石補救地形。先驗收沒有新增裝飾的山坡光照。

光照穩定後：

- 地色保留大尺度自然分區，過渡順著地貌，不沿 tile 邊界。
- 近景若仍欠移動參照，只保留少量與陸地類型、坡度及高度相容的既有樹石；森林成簇、裸岩區用石，水面不生樹，不均勻鋪滿每個格子。
- 地標世界位置固定，跨近地重建邊界不跳位，進出視野平順淡出；維持有界實例數，不增加遍布全球的物件。
- 細微材質只在真的看得見的近距離出現，降低對比並使用合適 mipmap；先試現有素材，沒有可見收益就不加新貼圖。
- 海洋與陸地分開調色／受光；海面保持平順，不套用陸地的粗糙坡面效果。
- 遠山只加輕微距離淡化，增加前後層次。雲與大氣在地形驗收後恢復，避免雲的白霧把坡形沖淡。

**完成條件：** 近地有移動參照，高空沒有噪點或重複花紋；整體形狀先於小裝飾被看見。

### E. 接觸陰影按需要補，首輪不用昂貴投影

使用者要求的山坡立體感首先由正確的漫反射與補光完成。發射台／地面接觸感先沿用既有柔和接觸陰影，校準位置、深度和透明度。

若完成 B–D 後仍明顯漂浮，再獨立評估一個只覆蓋近發射台的小範圍 shadow map；地面接收材質也須支援，並實測成本。它不是消除全球格紋的必要條件。本輪不加全球即時山影、SSAO、多級陰影或體積雲。

**完成條件：** 山體明暗合理，台座與地面有接觸感；沒有將環境補光、坡面明暗與真正投影混稱為同一效果。

## 4. 檔案與資料範圍

| 位置 | 後續可能的修改 | 必須保護的既有行為 |
|---|---|---|
| `terrain.js` | 共用地形受光、移除不適當噪點 | 區域透明交接、深度、LOD |
| `global-terrain.js` | 連續法線、同一地色及載入時初始化 | 有界 cache、失敗回退、海岸與半球裁切 |
| `contact-ground.js` | 相同受光法線、參照物收斂 | 中心相對座標、厘米級發射台精度、碰撞貼合 |
| `scene.js` / `scene-art.js` | 飛行光源方向一致、補光／霧必要調校 | 組裝頁、鏡頭、分離、RCS、碰撞特效 |
| `global-terrain.py` / `bake-terrain.mjs` | 必要的純本色輸出；若量測需要則預烘焙法線 | 原頂點、索引、海岸、真實高度資料逐項核對 |
| `surface.js` / `surface-data.js` | 優先只讀重用；若新增法線取樣輔助則限顯示用途 | `heightAt`、水陸、碰撞、物理與 snapshot 語義 |
| `assets` / `geography.json` / `art.test.js` / manifest | 只有重烘焙或新增檔案時更新來源、hash、格式／清單驗證 | source／SCORM 資產一致、離線可開 |
| 既有 browser owner 與活動計劃 | 新增格紋／光照案例及實際證據 | 不把所有舊案例無差別重跑；registry ownership 正確 |

先保留全部地形拓撲和高度。移除已烘焙的方向性明暗時，優先只重算色彩屬性，不重新三角化全世界；若現有工具做不到局部重烘焙，先估算必要變更，再擴範圍。不能直接在量化後顏色上除一個估計陰影值冒充還原本色。

## 5. 性能約束與工作方式

- 保留每幀不超過 100 draw calls、100,000 triangles 的現有上限；這只是資源限制，不是流暢證明。
- 第一輪正確法線＋漫反射＋補光不增加全屏後製、不增加陰影 pass、不增加三角形。刪除多餘細節取樣，盡量抵銷新增光照成本。
- 每幀只更新少量光源／變換參數；高度差、法線及地色在載入、離線或既有近地重建時處理。
- 沿用全球最多 4 塊 active、6 塊 cache、2 個並行載入；法線等新增資料一起納入記憶體與回收計數。
- 手機／桌面可列舉紋理分別維持 48 MiB／96 MiB 預算；頂點法線額外記憶體另外列出，不能混入貼圖數字。包大小以現有約 16.49 MB 作基準，不套用已過時的早期 5 MB 目標。
- 兩個代表場景做同機新舊比較：近地 100 m，以及問題高空約 1,182.5 km；固定視窗、DPR、品質、鏡頭和快取條件。先短測找瓶頸，最後候選做三輪暖機與持續取樣，記錄 p50/p95、CPU、draw calls、triangles、資源。
- 候選版相對基準的 p95 惡化超過 10% 時，先查新增片元／載入成本與裝飾；不能只報仍在 calls 預算內。接近幀同步邊界時看三輪分布，不能挑最好一次。
- 另量首次法線準備與細塊載入，避免每幀變快但首次畫面或換區卡住。新資產有量測收益才加入。
- 品質降級可以減少裝飾、DPR 與可見細節，**不能讓低品質重新出現格紋或錯誤坡向**。

P36 的 SwiftShader 桌面近地 p95 已比 P34 增加；此輪以恢復合理光照及減少冗餘為優先，不再先增加裝飾後補救效能。桌面手機尺寸模擬仍不代表真 iPhone GPU 表現。

## 6. 驗收：直接對準使用者看到的問題

| 檢查 | 預期結果 |
|---|---|
| 零高度、單色球面，雲與細節關閉 | 看不到 10° 格界；光照平滑、隨球體曲率改變 |
| 同一座丘陵，測試太陽從兩個方向照射 | 向陽／背光關係反轉，山谷仍可辨；不是固定畫死的暗紋 |
| 同一平面沿同一 tile 邊界兩側取樣 | 排除真海岸／地貌變化後，沒有突跳的顏色或法線 |
| coarse／fine、區域／全球、近地／區域交接 | 靜止與緩慢移動均無方格閃現、亮度跳變、三角補丁 |
| 使用者約 1,182.5 km 北美視角 | 大陸連續；雲開／關都檢查，不能靠雲遮住格紋 |

| 日期變更線、極區、低品質 | 法線有限且朝外、無新接縫；降級不破壞受光 |

數值檢查先以標準化診斷畫面建立，避免真實地貌混進接縫量度：同位置 normals 的目標角差 <0.1°；單色零高度測試在接縫兩側扣除球體正常漸變後，8-bit RGB 差初步目標不超過 2/255。此為待實作的驗收門檻，尚未宣稱達成。若必須調整，先記錄原因，不能為了讓測試過關而放寬到看得見的格紋。

至少桌面 1280 × 800、手機非全屏 390 × 664，固定同一輸入狀態出前後截圖，並目視短片中的轉鏡／LOD 交接。使用現有 browser owner 擴充，先跑受影響專項；最後固定 runtime 再跑 source 與實際解壓 ZIP，保留發射台、接地、分離／RCS 等必要煙霧測試。

碰撞／物理若維持只讀，就以既有接地案例保護，不重新開發模型或評分。若實作擴及任何 shared core、資料 schema、資產格式，重新計算受影響測試選取。真正手機／Safari 長時間效能與 Moodle 檢查仍分開報告。

## 7. 交付順序與停止條件

1. **診斷原型**：只處理兩塊地形和零高度對照，證明接縫根因已被消除。
2. **光照樣板**：近地丘陵、發射台、高空大陸三張同狀態對照；先讓無裝飾地形成立。
3. **全場統一**：將相同法線／本色／受光規則接到各層級，核對資料、LOD、海岸與回收。
4. **必要細節及性能**：只加有可見收益的地標／距離層次，超預算先刪裝飾。
5. **交付驗證**：固定候選 runtime，完成 source／ZIP 及必要回歸，才進入既有 commit、push、部署及線上核對流程。

若第二步仍像塑膠格子或沒有可信的坡形，停止擴散到全地球；回到法線與本色診斷，不以增加樹、噪點、雲或後製掩蓋。

2026-10-25 這一輪只交付計劃；2026-10-26 使用者已明確要求依計劃修改程式，後續依上述分期實作及驗收。

## 9. P37 實作記錄（2026-10-26）

- 共同法線從既有 Surface.heightAt 取東西／南北高度差；在地理位置固定的切平面取樣，局部 1 km、全球 16 km，120–240 km 銜接帶平滑過渡。只將真正高度坡度強調兩倍，不再從三角形法線扣球面後放大八倍。海面保持徑向法線，極向使用穩定切平面。載入／既有近地重建時更新，非逐幀重算全球。
- 全球、區域、接觸地面與海面共用漫反射＋當地天空補光函數；飛行時物件主光跟隨同一太陽方向，組裝頁保留原攝影棚光。移除全域隨機色斑紋理，沒有新貼圖、後製、陰影 pass 或多邊形。
- 全球及區域只重烘焙本色；441 個全球 binary、區域 27,279 頂點原位置／高度／索引／海岸逐 byte 保留。素材生成器提供 --recolor，正常完整生成亦採用相同本色規則；新 invariant hash 與共點本色斷言保護來源閉包。
- 近地樹石改為較稀疏群聚，樹木受緯度、海陸、高度及坡度限制；沿用最多 81 個、兩個 InstancedMesh、世界固定位置及距離／品質淡出。這仍是示意參照物，不是生態或建築地圖。
- 首輪 source 原型六個 flows 已通過：共點／粗細法線差 0°，零高度球面法線誤差約 0.000003°，GPU 邊界曲率殘差 p95 1/255；改變測試陽光後單色山坡像素平均差約 38/255，發射台遮擋 0 pixels。此為原型界線；最後 source／ZIP、效能與部署識別碼以活動計劃 P37 的最終證據為準。

- 最後遠景調校按 12 km 地貌的畫面投影大小，在 1–24 CSS px 間平滑淡出坡面細節；不依 tile ID 或 LOD 分別計算，因此不產生新的分塊界線。全球本色移除暖溫帶單一高頂點的白色雪斑，保留緯度帶／乾濕配色與極區色。
- 本輪沿用原雲／大氣和柔和台座接觸陰影，未新增遠山霧或即時全球投影。法線初始化在本機約 60–71 ms，一次準備成本與持續 frame timing 分開記錄；真手機首次載入仍未驗，沒有宣稱零額外成本。
